Wayback, under the hood

A Next.js web app on your phone. The AI runs in the browser, the building data lives in files, and your parkings are stored in Firebase.

How it works, in plain language

  1. Dorm map file: every spot on the demo path and how they connect. Hand-written, never changes.
  2. Reference photos: ~20 dorm photos. A setup script turns each into a list of numbers (an embedding) with the CLIP model.
  3. AI in the browser: your snap becomes numbers too, and the closest reference photos are the guesses. That's the retrieval in RAG. Sign reading (OCR) gives the right guess a boost.
  4. Firebase: stores your Current Parking + History with small thumbnails. An invisible anonymous sign-in keeps them private to your phone.

The route is plain code: the Dijkstra shortest-path algorithm over the map's links. Each link becomes one glowing step.

Components

Location Matcher Capturing · Fixing a Wrong Location
  1. Resize the photo → CLIP embedding (512 numbers)
  2. Cosine similarity against every reference photo
  3. Each spot's score = its best photo
  4. OCR words that match a spot's signText → +0.10 bonus (tune it)
  5. Return the ranked spots. The user always ✓ confirms, so there's no threshold

lib/matcher.ts · lib/scoring.ts (tested)

Locate Flow Capturing · Fixing · Finding the Car · Help

One page, ?mode=park|car|help: Snap → Working → Result ✓ → Other Guesses → Sign Photo → List Picker.

app/locate/page.tsx · GuessCard · SpotListPicker

Route Planner Guiding to a Room · Finding the Car

findRoom → shortestPath (Dijkstra, cost = walking seconds) → toSteps. Links are one-way with a matching reverse, so "left" becomes "right" on the way back.

lib/route.ts (tested)

Step Diagram Guiding to a Room

SVG templates: lifts, turn, lift-ride, door, walk, stairs, half-stairs, cube, arrive. Each map link names its template and the highlight.

components/StepDiagram.tsx

Parking Store Capturing · Arriving and Parking History

getCurrent, listHistory, saveParking (moves an old current parking to history), endParking. Thumbnails are ~20–40 KB base64, and offline saves sync later.

lib/firebase.ts · lib/parkings.ts

Trip State · GPS Stamp · Setup Script
  • Trip State: React context mirrored to sessionStorage, so a refresh mid-route keeps your place
  • GPS Stamp: one reading, 5-second timeout, never blocks
  • Setup script: npm run embeddings → public/data/embeddings.json

When it breaks

  • The AI is slow to load → "Waking up the AI…". If it fails → list picker. Open the app once on Wi-Fi before the demo.
  • Wrong match → other guesses → sign photo → list
  • OCR reads nothing → image score only
  • Offline save → Firestore queues it
  • Unknown room → "doesn't know room ___ yet"

How to run & demo

  • npm run dev → localhost:3000
  • npm run embeddings after adding photos
  • Push → Vercel → open the https link on your phone
  • Record the phone screen at the dorm: park → room → Find my car → Arrived
  • Submit: a public GitHub repo + the video (the Vercel link is optional)

Useful unknown, cleared up

"Browser storage loses data on refresh?" No: it survives refreshes and restarts. What resets is React useState. You chose Firebase anyway. Trip State still uses sessionStorage, so during the build, refresh on the Directions screen and watch your step survive.
